# Changelog

Todos los cambios notables de INNOVA se documentan aquí.

El formato sigue [Keep a Changelog](https://keepachangelog.com/es-ES/1.1.0/), y el versionado sigue [Semantic Versioning](https://semver.org/lang/es/).

## [Unreleased]

### Added
- **Service Principal DEV (S0-5, issue #16)**: registrado SP `INNOVA-SP-DEV` en Entra ID con permiso `Dynamics CRM/user_impersonation` (delegated, admin consent granted) y mapeado a Application User con rol `System Administrator` en la BU raíz del environment DEV. Nuevo archivo [`.env.dev.template`](.env.dev.template) con la estructura de las 4 variables (tenant id, client id, client secret, env URL); el `.env.dev` real queda gitignored. Nuevo script [`scripts/setup/auth-sp.ps1`](scripts/setup/auth-sp.ps1) que lee `.env.<env>`, crea/recrea el perfil `pac auth` (`innova-sp-dev` / `innova-sp-qa`) sin exponer el secret en logs, y valida con `pac org who`. Idempotente (borra y recrea si existe), soporta `-WhatIf`. Nuevo runbook [`docs/runbooks/05-service-principal.md`](docs/runbooks/05-service-principal.md) con setup paso a paso, distribución del secret al equipo (canal seguro, NO chat/email), tabla de GitHub Secrets para CI/CD (`PAC_DEV_*` / `PAC_QA_*`), procedimiento de rotación a los 24 meses, y tabla de diagnóstico de errores comunes (AADSTS, role-related, BU equivocada). Desbloquea #19 (flow template con connection refs) y las sub-tareas (e)(f)(g) diferidas de S0-6 (auto-import + smoke test en CI). **Pendiente del usuario**: replicar el setup para QA cuando se requiera CI auto-deploy
- **CI/CD ampliado + Release pipeline (S0-6, issue #17, parcial)**: export inicial de `innova_core` desde DEV (220 archivos, 2MB) versionado en `solutions/innova-core/` — antes del PR el folder estaba vacío y el job `validate-solutions` nunca ejecutaba. Round-trip pack verificado (117KB unmanaged). Workflow `.github/workflows/ci.yml` mejorado: `validate-solutions` ahora sube los ZIPs como artifacts en cada PR (7 días retención) como evidencia de smoke pack. Nuevo workflow `.github/workflows/release.yml`: dispara al hacer push de tag `v*.*.*`, empaqueta cada solution como **Managed**, genera `deployment-settings.prod.template.json` con placeholders para Env Vars + Connection References, calcula `SHA256SUMS.txt`, extrae release notes desde `CHANGELOG.md` con footer estándar (instrucciones cliente + recordatorio ADR-0004), y publica GitHub Release con todo (prerelease automático si tag tiene sufijo). Validator extendido con check 4e: componentes en `solutions/<sol>/{Entities,OptionSets,Roles,CanvasApps}/` deben tener prefix `pas_` (whitelist: `SystemUser`, `general`, roles `INNOVA *`). Bug fix: validator ahora excluye `docs/conventions/validation.md` del secret detection (falso positivo por documentar los propios patterns). Nuevo runbook [`docs/runbooks/04-deploy-release-cliente.md`](docs/runbooks/04-deploy-release-cliente.md) con proceso completo de deploy en tenant cliente (SP + Application User + Connections + import + roles + seed real). **Diferido a #16 (SP)**: sub-tareas (f) auto-import a QA con SP secret, (g) smoke test post-import — requieren Service Principal. Sub-tarea (d) `pac power-fx` descartada: solo tiene `repl`/`run` interactivos, no es linter de archivos
- **Patrones canónicos Power Fx (S0-7, issue #18, parcial)**: nuevo doc [`docs/conventions/power-fx-patterns.md`](docs/conventions/power-fx-patterns.md) con 16 patrones canónicos copy-paste-ready: variable global/contexto/collection, named formulas, `Patch()` con `Defaults()`, `IfError()`, navegación, formato fecha es-CR, delegables vs no-delegables, multi-statement `;;`, `IsBlank()`/`IsEmpty()`, lookup de parámetro tipado, filtros encadenados N:1, mostrar/ocultar por rol, patch a tabla puente N:M, tema visual desde `pas_parametro`, más sección "cuándo NO usar Power Fx". Bootstrap de la app `INNOVA - Patrones Power Fx [REFERENCIA]` en DEV, versionada en [`solutions/innova-canvas/referencia-patrones/`](solutions/innova-canvas/referencia-patrones/). **Descubierto durante implementación**: `pac canvas pack` con layout `SourceCode` está en Preview y falla con `FormatException` en el round-trip standalone — workflow productivo documentado en [`solutions/innova-canvas/README.md`](solutions/innova-canvas/README.md) usa `pac solution export/import` (estable) hasta que el formato YAML pase a GA. `.gitignore` extendido con `**/Src/_EditorState.pa.yaml` (estado del editor, no funcional), `**/AppCheckerResult.sarif` (output regenerable) y `.work/` (área temporal de download)
- **Framework de tests INNOVA (S0-9, issue #20)**: estrategia diferenciada por tipo de artefacto en `tests/{smoke,flows,canvas,plugins,pcf}/`. Plantilla [`tests/_template-test-plan.md`](tests/_template-test-plan.md) para test plans manuales (flows/canvas/smoke). Sample NUnit [`tests/plugins/Sample.Tests/`](tests/plugins/Sample.Tests/) que demuestra la cadena de build (15 tests pasando local, ejemplo basado en `ConsecutivoFormatter` de G7). Sample Jest [`tests/pcf/sample/`](tests/pcf/sample/) que valida tooling PCF (14 tests pasando local, ejemplo basado en `classifyEisenhower` de M-PRIO Phase 2). Decisión documentada en [ADR-0005](docs/decisions/0005-tooling-de-tests.md): **NO usar Power Apps Test Studio** durante MVP (frágil, mal versionable, no corre en CI, ROI bajo); test plans manuales con evidencia versionada en PR. Ejemplos manuales en [`tests/flows/iniciativa-creada-notificar-pmo-test-plan.md`](tests/flows/iniciativa-creada-notificar-pmo-test-plan.md) y [`tests/canvas/m02-solicitante-test-plan.md`](tests/canvas/m02-solicitante-test-plan.md). CI extendido con jobs `test-samples-dotnet` y `test-samples-pcf` que validan automáticamente los samples

### Changed
- **Modelo v1.4**: reconciliados los 17 labels de `pas_iniciativa_estado` con el cuadro resumen del cliente (EPIC #27, issue #33). Values numéricos preservados (no había datos en DEV/QA). 16 labels actualizados via `UpdateOptionValue` API. Nueva función `Update-DataverseGlobalOptionSetLabel` en `scripts/setup/lib/dataverse.ps1`. ### Added
- **Seed de catálogos placeholder (S0-10, issue #21)**: nuevo script `scripts/setup/07-seed-catalogos.ps1` que pobla los catálogos base con valores placeholder identificables (`(placeholder)`, códigos prefijados `CC-/DEPT-/SYS-`, dominios `placeholder.local`). Crea: 3 empresas con `pas_codigo_corto`, 9 centros de costo (3×empresa), 9 departamentos (3×empresa, consume G1), 9 sistemas (3×empresa, consume G2), 5 plantillas de correo genéricas (notificación PMO, estimación jefatura, aprobación gerencia, recordatorio 3 días, voto Comité) con variables documentadas, 3 miembros del Comité usando el usuario corriente como titular placeholder. Idempotente: 38/38 SKIP en segunda ejecución. Actualizado `scripts/README.md` con provisioning end-to-end y convención de placeholders. Patrón usa `pas_<Lookup>@odata.bind` (PascalCase nav property) en lugar del LogicalName snake_case
- **Parámetros operacionales sembrados (G8, issue #35)**: nuevo script `scripts/setup/06-seed-parametros.ps1` que pobla 12 parámetros en `pas_parametro` con valores default (tarifas hora PMO/Desarrollador, umbral escalamiento Comité USD, regla multi-empresa, horas por complejidad, días recordatorio, branding logo + colores). Idempotente: skip si la clave ya existe (preserva ajustes del admin). Flag `-ForceUpdate` para reset. Nuevo doc [`docs/architecture/parametros.md`](docs/architecture/parametros.md) con patrón de lectura desde Power Fx / Flows y reglas para agregar nuevos parámetros. Aplicado en DEV (12/12 creados, segunda ejecución 12/12 skipped)
- **Modelo v1.5**: nuevas columnas para el algoritmo de consecutivo `COA-AAAA-NNN` (EPIC #27, issue #34). `pas_empresa.pas_codigo_corto` (Text(3), required) y `pas_iniciativa.pas_consecutivo_secuencia` (Integer 0-999999). Nuevo doc [`docs/architecture/numeracion-consecutivos.md`](docs/architecture/numeracion-consecutivos.md) con algoritmo completo, validaciones, estrategia anti-race (Power Automate `Concurrency Control=1`) y pruebas mínimas. Aplicado en DEV (2 columnas nuevas en tablas existentes). Implementación del flow helper queda pendiente — referenciada por #19 (S0-8)
- **Modelo v1.3**: nueva tabla `pas_sistema` (catálogo de sistemas integrables hijo de `pas_empresa`) + tabla puente N:M `pas_iniciativa_sistema` (UserOwned). Alineación con requerimiento del cliente G2 (EPIC #27, issue #29): "Sistemas a integrar: lista desplegable parametrizable, catálogo por compañía, selección múltiple". Bridge usa Cascade Delete hacia `pas_iniciativa` (cleanup automático) y Restrict hacia `pas_sistema` (protege catálogo). Aplicado en DEV (2 tablas + 3 relaciones + 29 privilegios nuevos → 189 totales)
- **Modelo v1.2**: nueva tabla `pas_departamento` (catálogo de departamentos hijo de `pas_empresa`) — alineación con requerimiento del cliente G1 (EPIC #27, issue #28). Soft-delete pattern (`pas_activo`). Filtrado por empresa en la UI vía relación N:1 `pas_departamento_empresa`. Permisos: Read Global para los 7 roles + CRUD Global para `INNOVA Administrador`. Aplicado en DEV (1 tabla + 1 relación + 12 privilegios nuevos → 160 totales)
